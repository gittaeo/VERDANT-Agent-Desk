# 에이전트 데스크 설계와 검증 범위

## 제품 요구

기존 국내 주식 리서치를 보존하고, 역할별 작업·근거·반대 검토·종합 결과를 실제 실행 데이터에 연결한다. 사용자가 제공한 관제·가상 사무실 목업은 첫 화면을 대체하지 않고 에이전트 데스크 내부 탭으로 구현한다.

## 데이터 흐름

1. `POST /api/desk/run`: 시장·검색어·서버에 설정된 모델 모드만 받는다. 키·모델 URL은 브라우저가 지정하지 못한다.
2. `runDesk`: CHIEF 배분 → SCAN 실제 조회 → VET 조건 검사 → BOOK 맥락·연결 범위 → SIZE 검증된 입력만 계산 → FILLS 무주문 기록 → RISK 검사 → 선택형 LLM 검토 → 종합.
3. NDJSON `event`는 seq·UTC 시각·역할·상태·메시지·선택적 근거 ID와 검사 결과를 보낸다. 각 화면은 동일 이벤트를 사용한다. 사용자 화면의 시간은 한국 시간이다.
4. `result`는 당시 자료·규칙 버전·상태·출처·핵심 요약을 포함한다. PC는 서버 파일, 호스팅은 브라우저에 저장한다. 취소·실패는 완료 기록으로 저장하지 않는다.
5. 관제의 막대는 담당자 이벤트 개수를 표현한다. 가격·보유자 추이처럼 보이는 임의 차트를 생성하지 않는다.
6. 사무실은 DOM/CSS 기반 시각화다. `running` 상태인 실제 담당자만 움직인다. 움직임 감소 설정을 존중한다. 역할 클릭은 해당 실행 기록을 보여준다.

## 모델 경계

`rules` / `ollama` / `compatible` 프로필을 서버 환경에서 만든다. 외부 모델은 HTTPS 또는 로컬 주소만 허용한다. 모델별로 역할·입력 자료를 주고 근거 ID를 가진 JSON 요약을 요구한다. 응답에서 공개 요약만 읽고 모델의 thinking 필드는 사용하지 않는다.

현재 선택형 LLM 호출은 BOOK, RISK, CHIEF 세 검토 역할이다. 모델 호출 실패·잘못된 JSON·없는 근거 ID는 해석 실패로 표시하며 기존 계산 결과를 보존한다. 모델에 파일 시스템·지갑·주문·셸 도구를 주지 않는다. 자료와 명령을 분리하되 모델 출력의 사실성은 별도 검토가 필요하다.

BOOK의 해석은 `agent_review`로 구분해 RISK에 전달하고, RISK는 그 해석의 반대 근거·누락·상충 자료를 검토한다. CHIEF는 두 검토를 종합한다. AI 해석만으로 다른 AI 해석을 입증하지 않도록 최소 한 개의 원자료·규칙 검사 ID를 요구한다. 같은 모델의 여러 역할은 오류가 상관될 수 있으며 독립 전문가 합의나 정확도 보증이 아니다.

모델 호출에 사용되는 API 키와 금융 데이터 키는 결과·출처·진행 이벤트에 포함하지 않는다. 모델 상태 API에는 이름·설정 여부만 노출한다. 지원되지 않는 제공사는 JSON 응답 기능을 조정하는 별도 어댑터가 필요하다.

## 원장과 감시

원장은 `observation_only`다. 별도 호가·유동성 시뮬레이터 없이 실제 체결 성과로 사용해서는 안 된다. 위험 감시는 분석 요청과 별개인 로컬 서버의 5분 타이머로 돈다. 원장 변경을 직렬화하고 저장 파일을 임시 파일에서 원자적으로 교체한다. 읽기 실패를 새 빈 원장으로 덮어쓰지 않는다.

시세 장애는 unpriced로 남는다. 매수·매도 수수료를 각각 기록한다. 지갑이나 금융 주문 인터페이스는 없다. PC가 종료되거나 서버 프로세스가 중단되면 감시도 멈춘다. 웹은 원장 기능을 제공하는 것처럼 표시하지 않는다.

## 완료한 범위

- 기존 주식 리서치와 새 코인 분석 연결, 역할별 실행 상태·근거·계산.
- 세 가지 시각화 탭, 취소, 오류, 빈 후보, 부분 자료, 분석 이력, JSON 내보내기.
- 선택형 Worldmonitor 세 API 독립 검사. HTTP 200과 데이터 준비 상태 분리.
- 로컬 및 호환 API 모델 어댑터·근거 ID 검사·실패 처리·엔진 선택.
- 로컬 관측 원장·수수료·자동 위험 검사·재시작 후 복구.
- 공개 시세의 실제 조회와 UI 확인. 비밀키가 필요한 주식 조회와 실제 LLM 추론은 키·모델 미설정으로 이 체크아웃에서 미검증.

## 별도 데이터·평가가 필요한 범위

1. 코인 보유자 시계열, 실소유자 단위 집중도(토큰 계정·풀과 지갑 구분), 매도 가능성 검사, 호가 시뮬레이션.
2. 코인 자동 진입: 위 검사와 시점별 전략 성과 평가를 먼저 연결해야 한다. 현재 생성되지 않는다.
3. 예측 시장: 질문 정합성, 실제 가격, 확률 추정, 시장별 수수료·결제 조건을 구현해야 한다. 현재 베팅하지 않는다.
4. 장기 수정주가·기업행동·시점 보존 뉴스·시장/업종 비교. 기존 최대 5거래일 자료만으로 미래 수익률을 검증할 수 없다.
5. 자체 LLM 학습: 검수된 입력·출처·답안·반대 근거와 평가 분리를 먼저 구축한다. 저장된 모든 AI 출력을 자동 정답으로 학습하지 않는다.
6. 클라우드 원장·상시 감시: 사용자별 영속 저장소, 작업 큐·스케줄러·중복 실행 방지와 인증을 추가해야 한다. 현재 PC 원장과 웹의 기록은 동기화되지 않는다.
